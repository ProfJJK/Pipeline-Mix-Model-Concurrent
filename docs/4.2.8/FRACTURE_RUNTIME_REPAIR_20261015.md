# Receipt-bound fracture integration

The failure dossier and all three research channels feed a typed fracture plan.
The controller captures that plan on the ordinary task board and requires an
independent model to review its exact hash. The accepted graph retains the
original shared failure lineage, original requirement coverage, assembly scope,
raised assembly/final-test floor, and high-tier owner approval gates.

Registered children use individual native job fences and their exact compiled
profiles. Their output and cleanup receipts advance the existing microtask DAG.
The original failed native job remains immutable and blocked. An original-ID
artifact alias becomes usable only after the terminal physical verification and
any required independent content review. That alias refers to the concrete
tested final snapshot; it is not a synthetic native completion.

Planning and reviewing have separate stable control lineages and cumulative
dispatch/time limits. Execution children share the failed task's remaining
10/20/30 quality budget. A lower-tier implementation fragment is permitted only
when its exact classification/profile/scope matches the committed fracture graph.
Assembly and final-test floors are retained.

Source validation: 43 inert tests passed across fracture planning, cumulative
budgets, ordinary microtask dispatch, and physical retry coordination. These do
not establish host acceptance.

The integrated artifact adapter now has temporary-file/SQLite regressions for
an implementation fracture, a fracture inheriting existing artifact dependencies,
and a failed original final-test fracture through parent release. Test files
remain assigned to the terminal testing role. A separate nested-boundary test
executes the inner graph and proves that its verified immutable alias advances
the obsolete outer registered child without rewriting the failed job or its
20-failure history. It does not attest the later outer routing amendment.

An ordinary pivot of a registered child into tiers 8–10 captures a new owner
approval request bound to the exact failed source job, source node and intent,
compiled graph, dossier, shared lineage and original WBS generation. Existing
SRS or sibling approvals cannot satisfy that request. The authenticated owner
receipt commits the exact request hash. A source regression reaches the second
failure boundary, rejects a wrong owner token and a changed generation, and
commits the reviewed pivot while keeping all 20 failures.

Current integration evidence: four physical-source regressions and 20 fracture/
pivot regressions passed using inert native ports, real temporary files and
SQLite. The fixture called physical does not invoke native providers, Docker,
SYSTEM tasks, elevation or deployment. Final package integration still needs
the root lane's pending-sibling research parking and reviewed route-amendment
changes, plus whole-task promotion; none of these source results claim that the
installed host has accepted 4.2.8.
