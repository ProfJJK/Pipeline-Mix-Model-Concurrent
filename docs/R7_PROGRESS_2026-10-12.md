# R7 protected catalog activation — source preparation

Scope is the confirmed draft in `R6_DESIGN_20261011.md`: the SYSTEM Warden
reads protected catalog authority, probes using a free shared slot, then atomically
publishes a generation without rewriting historical job captures. There is no
loopback activation endpoint: the owner token is readable by agents. Optional
batch/canary/sentinel proposals are not added to this scope.

Implemented the pure change-plan compiler in `catalog_activation.py`:

- Binds exact proposal bytes and the expected current policy digest.
- Rejects duplicate/unknown fields, legacy policy migration and reused generations.
- Keeps operational budgets, backoffs, pools and matching model caps intact;
  refuses to silently discard an explicit cap on a retired target.
- Captures immutable candidate bytes, deduplicated changed targets and an existing
  control target. Mutating the input/projection cannot alter its digest.
- Requires new generation identity even for reorder-only changes, with a control
  probe planned. A plan explicitly grants no activation authority or acceptance.

## Retained protected authority reader

`catalog_authority.py` now prepares the SYSTEM-only reader. Its production entry
point accepts no pathname and reads the fixed Program Files catalog authority
root. It retains ancestors top-down against rename/deletion and holds the pointer
and proposal files against writing or replacement through the caller's context.
ACL validation follows acquisition, reparse objects/hardlinks are rejected, and
the proposal leaf is derived exclusively from its pinned SHA256. Strict bounded
pointer parsing rejects duplicate keys, extra paths, invalid IDs and oversized
files. Failure or caller exceptions release handles in reverse order.

The Windows adapter is tested with injected API/metadata fixtures; these are not
native share-mode or SYSTEM ACL acceptance. No protected directory was created or
read by these tests. This reader does not publish a generation, reserve a slot or
grant loopback authority. Remaining integration listed above is still required.

## Transactional publication primitives

`catalog_journal.py` adds explicit transaction-bound journal initialization and
generation publication, currently **not installed or invoked by JobStore**.
It requires FULL synchronous writes and foreign keys, preserves immutable
generation history, checks the expected prior policy, and publishes through an
atomic singleton pointer update. A replay returns the old request's receipt
without moving the active pointer backward. Initialization refuses an unrelated
installed baseline. Probe projections must exactly cover changed targets plus
the control and bind request, plan, cleanup and reservation identities.

These checks do not prove that a supplied reservation was live: the upcoming
JobStore integration must verify and consume real shared-slot reservations in
that same transaction. No controller/API path can call publication yet. Tests
cover transaction rollback, concurrent-reader visibility, reopened-file recovery,
replay/stale proposals, missing cleanup and unbound proofs, using temporary SQLite
only. The prior R6 package is untouched.
